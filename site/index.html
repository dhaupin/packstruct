THE SHARED /PACKS SPEC

One manifest. Many hosts.

packstruct defines how a /packs directory works - manifest, entry contract, lifecycle, refusals - so an author who writes one pack knows how packs work everywhere. Currently hosted by crashtest (scenario profile) and poststruct (check profile).

The contract

packs/public/<name>/ carries a frozen pack.json (schemaVersion 1, name matches directory, entry must exist) plus its entry module. A manifest declaring a file that doesn't ship is an instant, nameable refusal - never a deep import stack trace.

The linter

npx packstruct lint packs/ - zero dependencies, kills the missing-entry class at author time, in any fleet repo. Machine-readable with --json.

npx packstruct lint packs/

Profiles

The manifest surface never forks; execution semantics are declared as profiles: scenario (crashtest: hostile scenarios against a transport, isolated) and check (poststruct: pure-reading verifiers over files on disk).

Docs

The full spec, conformance rules, and versioning live in the docs site: docs.creadev.org/packstruct (Jekyll + Pagefind + freestruct - the triple dogfood).
